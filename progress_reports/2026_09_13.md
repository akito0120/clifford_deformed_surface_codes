# Specification and Architecture

As I promised in the last meeting, I share the specification and the architecture here, with slight modification.

## 1. Scope

We study static clifford-deformed surface codes in this simulation. More specifically, a code falls into our scope of study if it satisfies the following criteria:

| Criteria | Why it is required |
|---|---|
| Static | The same stabilizers are measured every round, so a detector is the comparison of one ancilla between adjacent rounds. This condition is required to automate the circuit building process |
| Commuting | Otherwise the generators do not define a stabilizer group. |
| 1 logical qubit | For fair comparison and automated circuit generation |
| 2D lattice | 3D or higher dimensions cannot be modelled |

For example, rotated surface code and its hadamard deformed version, XZZX code, are from this family of codes. Floquet codes are examples of codes that are out of the scope.



## 2. What the User Provides

User provides 3 things:

- Code definition
- YAML config file
- Commands

### 1. Code Definition

A code definition is a pure data record containing information needed to build stim circuits, defined in [definition.py](../src/cdsc/codes/definition.py) as a dataclass.

Uses can register their own code definitions by writing a function decorated with `@register_code`, returning a `CodeDefinition` instance. You can find built-in code examples in [builtin.py](../src/cdsc/codes/builtin.py).


### 2. YAML config file

One simulation needs one YAML config file, providing all parameters for the codes, noise, sampling, analysis etc.
Below is an example of a configuration file:

```yaml
experiment:
  name: css_xzzx_comparison
  seed: 0

codes:
  - id: css
    builder: rotated_surface
  - id: xzzx
    builder: xzzx

noise:
  model: circuit_level # code_capacity | phenomenological | circuit_level
  channel: biased # depolarizing | biased
  params:
    eta: [0.5, 1, 10, 30, 100, inf]
  rounds: distance # "distance" or an integer
  p_meas: same_as_p # "same_as_p" or a number

sweeps:
  - id: threshold_window
	resume_file_path: results/resume_threshold_window
    distances: [11, 13, 15, 17, 19]
    basis: [X] # X, or Z or both
    p:
      mode: window # window | list | linspace | relative
      step: 0.0001
      half_width: 0.003
      center:
        css:  {0.5: 0.007, 1: 0.0065, 10: 0.006, 30: 0.006, 100: 0.006, .inf: 0.006}
        xzzx: {0.5: 0.007, 1: 0.0078, 10: 0.013, 30: 0.016, 100: 0.019, .inf: 0.022}

  - id: subthreshold
	resume_file_path: results/resume_subthreshold
    distances: [5, 7, 9, 11, 13]
    basis: [X]
    p:
      mode: relative
      ratios: [0.30, 0.40, 0.50, 0.60, 0.70]

sampling:
  decoder: mwpm # mwpm | bp | uf
  max_shots: 300000
  max_errors: 30000
  max_batch_size: 1024
  workers: auto # "auto" or an integer (number of workers)

threshold:
  source_sweep: threshold_window
  distances: [11, 13, 15, 17, 19]
  nu_init: 1.1
  x_window: 0.006
  bootstrap: 5000

suppression:
  # Currently being designed

output:
  dir: results/css_xzzx_comparison
  figures: true # Generate figures from CSV
  diagrams: false # Generate diagrams from stim circuit
```

### 3. Commands

This framework supports the following commands:

- `validate <config-file-path>`: Validates specified code definitions and stim circuits, then generates a report
- `run <config-file-path>`: Runs the sampling and decoding, then emits a CSV file `samples.csv`
- `analyze <config-file-path>`: Reads `samples.csv` and estimates the threshold, suppression factor and teraquop footprint, then write the results in a file
- `visualize <config-file-path>`: Reads the analysis result from the file and visualize it, and generates a stim diagrams 
- `run-all <config-file-path>`: Runs all of the above steps


## Layers, Inputs and Outputs

| Layer | Inputs | Outputs |
|---|---|---|
| Code | User defined code definitions | Registered code builder |
| Circuit | User defined codes registered in the registry, noise models, distance | stim circuit | 
| Validation | User defined code and generated stim circuit | Validation report `validation.json` |
| Sweep | YAML config file | `samples.csv` |
| Analysis | YAML config file and `samples.csv` | Estimated threshold, suppression factor and teraquop footprint |
| Visualization | Analysis result from the analysis layer and stim circuit | Analysis result figures and circuit diagrams |

Aside from the outputs from each layer, a manifest file `manifest.json` containing everything needed to reproduce the experiment should be generated.
